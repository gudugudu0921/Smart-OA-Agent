# Smart OA Agent 5–10 分钟演示脚本

本脚本使用 Docker Compose 的统一入口，面向本地演示或受控的小范围测试。所有姓名、部门、邮箱和审批内容都应为虚构数据。

## 首次准备

1. 按根目录 [README](../README.md) 创建本地 `.env`，不要在投屏、截图或聊天中展示其内容。
2. 构建并启动服务：

   ```bash
   docker compose up -d --build
   docker compose ps
   ```

3. Fresh Install 中执行一次管理员引导：

   ```bash
   docker compose exec backend python -m app.db.create_admin
   ```

4. 安全保存终端显示的一次性临时密码，首次登录后立即修改。项目不提供公开默认密码。
5. 由管理员在用户管理页面创建至少一名员工、一名主管和一名 HR 测试账号，并为他们设置虚构资料和临时密码。
6. 访问默认入口 `http://localhost:8080`，确认页面可用；必要时检查 `/api/health` 和 `/api/ready`。

如果复用已有数据库，不要再次把 bootstrap 当作迁移工具。先备份数据，再按 README 的 Existing Database 指引运行迁移。

## 演示流程

1. 使用员工测试账号登录，说明 JWT 代表后端校验后的真实身份，并完成任何首次登录改密提示。
2. 在 Agent 中新建会话，输入“我要请假”，展示缺少字段时系统继续追问而不会直接写入业务数据。
3. 补充互不冲突的未来日期、请假类型和虚构原因，展示多轮对话 checkpoint 与生成的申请编号。
4. 切换到主管测试账号，打开通知和待办，查看新的请假审批。
5. 在主管审批页批准申请并填写不含敏感信息的意见。
6. 切回员工账号，展示申请进入下一审批阶段。
7. 使用 HR 测试账号查看通知、待办并完成终审。
8. 再次切回员工账号，展示最终状态，并演示单条已读和全部已读。
9. 使用管理员账号打开审计日志，按申请编号或操作类型筛选创建、主管审批和 HR 审批记录，查看结构化详情和 Request ID。
10. 总结系统边界：MySQL 是业务事实源，Redis 承载 Agent 会话状态；删除聊天会话不会删除业务申请，撤销请假采用业务状态变更而非物理删除。

## 可选故障演示

在受控环境中停止 Redis 后，验证登录、通知、待办、审计和传统请假接口仍可使用，而依赖 Redis 的 Agent 会话返回明确的服务不可用响应。恢复 Redis 后重新创建会话并验证读写。

不要在共享环境随意停止基础服务，也不要为了演示执行 `docker compose down -v`，因为 `-v` 会删除 Compose 管理的数据卷。

## 演示结束检查

- 登出所有测试账号，不共享浏览器中的令牌或 Cookie。
- 对外分享前检查截图和日志，移除临时密码、Token、API Key、真实邮箱、内部地址和本地路径。
- 记录异常对应的 `X-Request-ID`，只分享最小且已脱敏的日志片段。
- 测试数据应保留还是清理，由测试负责人按审计与隐私要求决定。
